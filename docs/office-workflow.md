# 办公任务工作台

ZSense 的每轮本地对话、已授权消息网关请求都会建立持久任务记录，关联 Bot、会话、来源消息、工具步骤、文件证据、结果和交付状态。主入口在左侧「任务工作台」。任务和检索条目随所属会话/Bot 删除而清理。

## 文件链路

钉钉使用原始消息和 `quotedMessage`/资源 ID 定位附件；飞书使用消息资源定位附件。入站去重键是连接 ID + 平台消息 ID。来源文件必须下载成功，才能让 Agent 继续处理；未落盘时任务失败，不会让模型猜测文件内容。处理后重新读取磁盘文件并记录 SHA-256。`read_pdf` 的页码和 `read_spreadsheet` 的选区会写进来源证据。

钉钉/飞书文件任务和生成文件的任务会进入「等待审核」，由用户在工作台确认后再向原会话回传。飞书使用消息 API 先发送已验证的产物文件，再发送文字结果，逐个保存平台接受回执。钉钉机器人当前仅保证文字回复；有生成文件时会在确认框中说明，结果会明确标为「仅文字已发送，文件未上传」，不得误报完整交付。

## 检索与恢复

本地 SQLite FTS5 索引本 Bot 已处理的消息、回答和工作区文件（文本、CSV/TSV、PDF、DOCX、XLSX、PPTX）。文件按大小与修改时间增量更新；PDF 使用本地解析器，Office 使用内置 officecli。任务工作台和 Agent 的 `office_knowledge_search` 均强制 Bot 范围，不能跨 Bot 检索。它不扫描或索引未参与任务的整个磁盘。

失败会分类并保留错误，不自动重放外发/删除等有副作用操作。应用退出时的运行/发送中任务，以及失去原平台回复通道的待审核任务，重启后标为「已中断」；处理结果仍可在任务工作台查看，但需从原平台重新发起回传。飞书同一次审核中的已接受文件回执会保存，网络失败后重试时不会重复发送这些文件。

本地回归：`npm run test:office-tasks`、`npm run test:gateway`；全套：`npm test`。

## 2026-10-10 Office 编辑与性能优化

三套编辑器共用持久化服务、文件版本检查和 Agent 事件，不再分别维护互不相通的临时结果。原始文件只在手动保存成功后替换；未保存修改、可见预览及正在加载的文件不会被缓存清理。跳转会话、切换文件或进入浏览器/画布前会确认未保存内容；取消旧请求后，迟到的结果不能覆盖新文件。

- Excel/CSV：改单元格时合并内容和格式差异，支持清除格式；撤销到原值会消除待保存项。整批修改先验证，XLSX 在同目录工作副本应用并验证后原子替换；中途失败保留原件与草稿，重试不重复结构操作。CSV 保留换行格式。
- Word：使用 UTF-16 半开区间定位选中文本，局部 OOXML 修改保留未选中的富文本及链接。相同草稿不重复处理，新增修改只应用增量；预览更新保留 iframe、选区与滚动位置。Ctrl/Cmd+S 保存前确认最新草稿；外部预览必须经 iframe 确认应用，父端才切换版本。晚到预览和外部修改发生冲突时保留本地草稿，禁止过期写回。
- PPT：幻灯片缩略图、文字/图片/形状选中、文本和位置尺寸编辑、拖动与缩放、手动保存、局部 AI 编辑及 Ctrl/Cmd+S、Ctrl+滚轮缩放。工作副本与原件分离，保存前检测外部变化。响应以编辑代次和文档版本校验，等待期间的新输入不能被旧响应清除；本地草稿与外部新版本冲突时保留草稿并禁止过期写回。
- Agent：新增读/改/保存 Word 与 PPT 的六个工具，共享编辑器中的工作副本。工作区外保存必须经过现有文件写入审批；后台没有审批入口或用户拒绝时不写入。
- CLI 与缓存：全局最多 3 个 OfficeCLI 进程，同一文件按序执行，禁止隐式常驻进程；切换文件可取消过期任务。未变更文件复用预览和读取结果，干净缓存有数量及空闲时间上限。导出不能覆盖来源或 Office 文件；参数以空格、等号、冒号和附着短参形式统一校验，符号链接也不能绕过工作区边界。
- 取消与保存：Agent 取消信号贯通共享文件队列和 CLI，在原子写回前重新检查取消状态。取消排队操作、运行中的 CLI 或审批等待后取消，均不能迟到覆盖原件，未保存草稿保留；已经原子提交的保存会完整完成元数据收尾，不能误报为尚未保存。
