# 安装即用的本地长期记忆

当前实现借鉴 Hindsight 的“保留（retain）—召回（recall）—修订/遗忘”工作流，但不运行或下载 Hindsight、Python、uv、嵌入模型或独立数据库。ZSense 内置 SQLite 已包含全部需要的存储与索引逻辑，首次安装即可离线使用。

- 每个 Bot（含 AI 对话空间）使用独立命名空间，并进一步按可信用户归属和项目隔离。聊天、消息网关、定时任务、远程任务及记忆工具使用同一归属规则：本机对话属于 `local`，渠道归属由已验证的连接与发送用户确定，远程任务归属由已绑定设备确定；项目键由规范化工作区路径计算。模型和工具参数不能替换这些归属。用户通用记忆可在同一用户的项目中召回，项目记忆只在对应项目召回。
- 回复完成后仅检查用户原话；明确的长期事实/偏好才自动写入，问句、引用、转述、代码、临时要求、凭据和可疑指令会先过滤。姓名等短事实也可提取。未知事实只精确去重；已识别的回答语言、姓名、职业、公司、项目名称、输出格式使用固定事实键处理用户明确纠正，不能凭相似度覆盖其他事实。
- 召回使用中日韩分词片段、关键词覆盖度、记忆类型、置信度、时间及召回次数排序，并有条数和字符预算。SQLite 先按 Bot、用户和项目筛选；内存倒排索引与已分词缓存筛选相关候选，记忆变更时按版本失效，避免每轮全量扫描、重复分词。不会把完整历史塞入每次请求。
- 已投影到 SQLite 的旧 Hindsight 事实与原有人工记忆继续保留，可查看和编辑。旧 Hindsight 独立数据库中**尚未投影**的事实不会自动读取，升级前应先确认记忆管理界面所见内容。

无法确定发送用户的旧渠道自动记忆移入 `legacy-unattributed` 归属，继续供记忆管理界面查看，不会猜测原用户或召回到新的用户对话。旧记录迁移时保留保护状态，新增保护字段的旧库默认锁定；手动添加、修改记忆也默认 `locked=true`。是否允许自动纠正由保护字段决定，来源文字用于审计和自动容量计数，不代替保护规则；用户可在编辑界面明确解除保护。

自动纠正只修改同一归属、同一事实键下未保护的记忆。修订增加版本号，并保存最近五次旧标题、内容、原话证据、来源与更新时间，详情界面可查看。用户明确要求忘记已识别事实时，删除对应记忆；受保护记忆需用户在管理界面操作。手动删除同时清除该条修订历史，并留下防止后台重新添加的遗忘标记：仅保存规范化内容的 SHA-256 哈希及必要的归属、事实键元数据，不保留已删除正文或原话。此标记阻止自动重新添加，用户仍可主动手动添加。

自动记忆和后台整理使用队列、取消信号、任务代际和记忆库版本检查。手动编辑或删除、停止维护、关闭相关开关后，旧任务即使迟到返回也不能覆盖新状态或恢复已遗忘内容。记忆变更通知只更新对应空间的记忆，不替换正在显示的会话。定时任务滚动摘要同样校验任务修订和运行状态，已删除运行、停用任务或被用户修改的摘要不会被旧模型结果写回。

设置中的自动记忆上限默认为每 Bot 空间 500 条，可设为 50–5000。只统计自动记忆与周期整理等自动来源，受保护的自动来源仍计数；人工添加或修改后的记忆不占自动额度。满额时暂停自动新增并提示，纠正已有记忆不受新增额度限制。周期增量整理默认开启，每 10 轮符合筛选条件的用户消息触发一次，可设为 2–100；它只重试本进程最近缓存的至多 24 组已确认、因容量不足未保存的候选，不扫描全部历史、不清理过期记忆，也不承诺跨重启恢复待保存候选。

两个额外模型开关彼此独立，默认均关闭：

- `memoryModelRefinement`（模型精炼记忆）：后台发送本轮已筛选候选的连续原话、候选信息和相关记忆给当前配置的模型服务，不发送该轮其余段落或此前对话原话。模型可选择候选、改进标题；事实正文、类型和纠正键仍由可信本地候选确定，并重新检查逐字证据、敏感内容和保护状态，不能扩大用户或项目归属。
- `autoDistillSkills`（自动沉淀技能）：独立后台发送本轮用户请求、过滤后的执行摘要、现有技能名称及简短描述给当前配置的模型服务，判断是否生成可复用技能。它不依赖记忆精炼开关，也不阻塞正常回复完成。

配置为云端服务时，该服务会接收上述相应内容；设置开关旁明确显示这项说明。默认关闭时，记忆整理不产生额外模型请求。正常聊天仍使用用户配置的模型服务，召回到的相关记忆会作为对话上下文使用。

能力边界：这不是完整版 Hindsight 的本地 LLM 事实抽取或向量语义检索。默认本地规则只对明确表达的长期信息做保守提取；隐含事实、同义表达和复杂矛盾的处理能力较弱。无需首次下载、额外后台进程或嵌入模型内存，也不会把记忆内容上传到独立记忆服务。

## 旧设备升级后的首次整理

安装本版后首次启动，在加载记忆服务、模型及设备凭据之前执行一次本地召回质量整理，特性标记为 `local-memory-quality-v1`（不是每次升级版本都重复整理）。只处理已有 SQLite 工作区内的自动来源记录：明确的问句、引用/代码、临时状态、工具转录和敏感内容暂停自动召回；人工来源、未知来源、无法确定是否为噪声的记录保守保留。经过编辑并保护的自动记录也保留，敏感内容仍优先暂停自动注入。

整理只修改召回准入元数据，不删除或改写标题、正文、证据、归属、事实键、内容保护及修订历史，也不解除旧锁定记录。暂停记录仍可在记忆管理和显式搜索中查看，界面显示原因；用户手动编辑保存可恢复当前归属内的自动召回。自动索引和手动搜索索引分开缓存，整理后使相关 Bot 的旧索引失效。

未保护的已识别旧事实收到可信用户新原话的明确纠正后，按新内容重新判断准入，避免正确的新事实仍被旧暂停标记阻挡；无可信原话的模型结果不能自动恢复。schema 44 还补齐历史 `Hermes · ` 自动来源的归属隔离：外部渠道且仍标记为未证明的本机归属时移入 `legacy-unattributed`，不改已绑定的可信用户归属。此安全迁移与正文质量整理独立。

处理结果与完成标记在同一 SQLite 事务提交；失败全部回滚，不阻断启动，下次启动重试。新安装记录 `new-device` 标记而不扫描，后续重启也不误判为旧设备。流程不调用模型、不联网、不扫描聊天历史、不下载组件、不申请钥匙串或录屏权限，不新增确认弹窗。现有凭据初始化与 macOS 系统授权仍是独立流程，不能因此保证任何系统弹窗都消失。

回归入口：`npm run test:memory-upgrade`。安装器本身不读取用户记忆，也不承担数据迁移；实际整理在新应用首次启动时执行。

本轮相关验证入口：`npm run test:local-memory`、`npm run test:memory-intelligence`、`npm run test:memory-maintenance`、`npm run test:memory-integration`、`npm run test:memory-ui-model`、`npm run test:memory-entrypoints`、`npm run test:scheduled-memory-races`、`npm run typecheck`；合成基准为 `npm run bench:memory`。包检查入口仍为 `node scripts/verify-packaged-app.mjs`，不能替代实机验收。2026-10-10 本机固定签名应用已替换，源码全套 95 项回归通过；系统界面服务超时，未完成新面板 live 验收或钥匙串授权持久化复测。完整 Mac/Windows 安装、跨设备记忆迁移仍应分别验证。“导出配置”不含会话与记忆，不能当作备份。
