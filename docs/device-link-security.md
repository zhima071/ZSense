# 设备互联安全、交换中心与迁移

## 身份与设备号

- 每个桌面客户端首次运行时在系统安全存储中生成 Ed25519 密钥对；私钥不离开客户端，交换中心只保存公钥和公钥指纹。
- 公网设备号由交换中心随机分配，并永久绑定到首次注册公钥。客户端不能自选、抢注或覆盖设备号，公网地址固定为 `https://<设备号>.zsense.space`。
- 注册流程是“申请一次性挑战 → 客户端签名 → 中心验签”。注册、心跳、更新上游、主动下线和永久撤销都使用独立挑战；挑战 60 秒过期、单次尝试即消耗，签名消息包含操作、设备号、公钥指纹、上游和挑战到期时间。
- 公网设备默认每 3 秒尝试一次签名心跳，同一时刻只保留一个心跳请求；账号设备列表独立按 30 秒同步。交换中心的 75 秒离线判定窗口不随心跳频率改变。
- 中心重启后所有设备默认离线，必须重新签名注册；中心不会因为磁盘里有旧上游地址就恢复转发。

## 旧设备号迁移

升级后的中心会把没有公钥的旧映射标记为 `legacy`，清空上游并停止转发。旧号不能由客户端直接声明，也不能被新设备重新分配。

1. 在客户端“设备互联 → 远程连接”点击“复制迁移公钥”，把 PEM 公钥安全交给中心管理员。
2. 管理员在中心机器执行：

   ```bash
   cd /opt/zsense-hub
   node server.mjs bind-legacy <旧设备号> /安全路径/device-public-key.pem
   ```

3. 客户端重新打开远程连接。中心只会向刚绑定的同一把公钥发挑战；验签成功后旧地址恢复使用。

若旧号在中心从未存在，客户端不会保留它，而是让中心分配新号。永久撤销的设备号进入墓碑表，不能迁移、复用或被抢注。

## 首次配对与免密进入

- 局域网直连使用 HTTPS。接收设备展示 `6 位临时代码-16 位证书身份码`；发起设备在发送临时代码、设备公钥和共享凭证前，先核对 TLS 证书身份码。
- 临时代码用系统加密随机数生成，5 分钟过期；同一来源 1 分钟内最多失败 6 次。首次成功配对后，双方保存对方设备公钥及 TLS 证书指纹。
- 公网首次连接可使用前 6 位临时代码，但必须经目标设备的有效 HTTPS 地址访问。成功后双方交换并保存设备公钥，临时代码立即轮换。
- 后续公网免密进入优先使用单次请求：发起设备用 Ed25519 签名目标设备号、路由、毫秒时间戳和随机数；接收端校验已配对公钥、两分钟时间窗与随机数不可重放，再签发 90 秒内使用的一次性入场票据。旧版设备仍走目标设备挑战 + 签名换票据的双请求流程。邮箱、账号名和客户端自报的 `emailHash` 都不是认证凭据。
- 远程连接不依赖本机安全锁。直接打开远程网页时，有安全锁就校验安全锁密码；关闭安全锁后必须校验单独设置的远程访问密码，未设置时禁止密码登录。已配对设备仍可通过设备私钥挑战进入；首次设备配对使用短期配对码。任何路径都不会因安全锁关闭而免密放行。
- 同邮箱自动发现以交换中心验证结果为准：两台设备分别领取并提交绑定专用邮箱验证码，中心将已验证邮箱对应的账号 ID 持久绑定到各自 Ed25519 公钥；之后设备签名查询同账号设备号与公钥。客户端自报邮箱、邮箱哈希或本机旧邮箱记录都不能触发自动信任。旧安装须在“用户管理”重新验证一次。
- 同账号设备自动加入受信任列表并定期同步；互相进入远程页面仍须由设备私钥完成短时签名验证。云端链路可用性取决于双方开启互联和各自的网络状态。

## 权限、离线与撤销

- 新配对默认没有读取或远程执行权限。接收设备分别授权状态/Bot/对话、文件、远程任务。
- 邮箱验证带来的自动信任也默认关闭全部远程读取与执行权限。本机撤销设备后将设备号加入本机拒绝列表，下一轮同账号同步不会把它重新加入；如要恢复，必须重新显式配对。中心永久撤销设备号时会清除其账号绑定。
- 云端 Agent-to-Agent 任务由发送端用设备私钥签名，签名绑定 HTTP 方法、路由、一次性挑战和完整请求正文。接收端再次核验设备公钥及“允许在本机执行任务”；任务提交与结果查询使用独立短请求，避免长任务占满交换中心代理连接。同一设备的并发请求使用不同挑战，挑战数量有上限。
- 任务提交不会自动重放，避免网络超时后重复执行；若提交响应丢失，界面会报告“结果不确定”，需要检查接收端运行记录。撤销设备授权、关闭云端入口或停止网页桥接时会请求取消本机正在运行的远程任务。取消对不可中断的外部工具不保证事务回滚。
- 撤销受信任设备时，该设备的公钥授权、未使用挑战、一次性票据和已有网页会话立即失效。
- 关闭远程连接或设备互联总开关时，客户端先发送签名下线，再停止隧道并撤销所有远程网页会话。中心同时终止该设备的活动代理请求。通知失败时，中心 TTL（默认 75 秒）兜底下线。关闭安全锁或修改访问密码时只撤销旧远程网页会话，远程通道保持开启并重新要求验证。
- 隧道进程退出时客户端立即签名下线，并以 2、4、8、16、30 秒退避重连；得到新隧道地址后通过签名“更新上游”恢复路由。
- 永久撤销公网设备号会在中心保留不可复用的墓碑记录。下次启用需重新申请新号。
- 文件读取仍是高权限：一旦开启，受信任设备可以按路径读取非凭据文件。已知密钥文件和目录会被阻止，但不能保证识别所有自定义文件中的秘密。

## 转发与加密边界

这条链路**不是端到端加密**。浏览器到 Cloudflare、中心到公网设备上游分别使用 TLS，但 Cloudflare 可在边缘终止 TLS，交换中心的反向代理也能看到解密后的 HTTP 请求和响应。不要把它描述为 E2E。
设备签名只保证消息来源和内容在接收端可验证，并不隐藏 Agent 指令或结果。涉及高敏感数据时应只使用局域网链路，或在将来的端到端加密协议完成后再使用云端任务。

交换中心不保存对话、文件、密码、API Key、Cookie、配对码、签名或长期设备登录票据；它保存设备号、公钥、受控上游、状态时间、最小访问计数及经服务端密钥 HMAC 后的账号 ID，不保存绑定邮箱明文到设备注册表。日志只记录去掉查询串的路径、状态码和耗时，不记录请求/响应正文或认证头。邮箱验证只允许向交换中心明确配置的收件邮箱列表发信，不是任意邮箱注册服务。Android 伴侣端与桌面端共用此协议，手机只在验证邮箱后查询同账号设备；邮箱仍不是连接凭证。

## 上游安全边界

- 公网上游仅允许 HTTPS 443、无用户名密码、无路径/查询/片段，且主机名必须位于中心配置的后缀允许列表。
- 注册和每次转发都重新解析 DNS；任一 A/AAAA 结果落入回环、内网、链路本地、CGNAT、文档、保留或组播网段都会拒绝。代理连接固定到本次校验通过的 IP，避免校验后 DNS 重绑定。
- 中心不跟随上游重定向；仅透传相对路径或同源重定向，跨源和协议相对重定向返回 502。
- 客户端不能提交 `127.0.0.1` 等本机地址。本机上游只能提交固定标记 `local://web-bridge`，实际回环 URL 必须由中心管理员写入 `local-upstreams.json` 或 `ZSENSE_HUB_LOCAL_UPSTREAMS`。

## 版本兼容与验证范围

局域网协议为 v2。旧版 HTTP 配对记录没有证书指纹或设备公钥，不能继续发送带凭证的请求；两端更新后应撤销旧记录并重新配对。公网注册协议也为 v2，旧的无签名登记不会继续转发。

自动化测试覆盖模拟 macOS/Windows 双设备配对、设备号抢注、伪造注册、签名重放、SSRF、TTL 下线、撤销后访问、隧道断线重连和会话撤销；真实 Windows/macOS 硬件、防火墙、Cloudflare/DNS 与跨运营商网络仍须按交换中心仓库的联调文档验证。
